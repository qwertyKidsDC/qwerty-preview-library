SECURITY / QK LESSONS × BUILD07

Keep the junk out.

Mail filtering and website form protection are different jobs.

Spam Filters

Processing ON; threshold 5; Spam Box ON; auto-delete OFF. A genuine enrolment is more important than a perfect spam score.

Default Address

Reject unknown recipients for both domains at SMTP time. No catch-all or BoxTrapper.

Domain authentication

SPF, DKIM and DMARC now valid. Review DMARC policy with owner; monitor before tightening. Never add duplicate SPF records.

Account security

VIPcontrol email 2FA enabled. Separate cPanel 2FA deferred. Owner holds credentials, recovery codes and session access.

Confirm reported settings without changing them blindly. Never capture private dashboards, keys, session URLs or real family details.

The booking journey.

The teacher confirms availability before an invoice is sent.

Parent
Enrols + reviews→QL backend
Validates + calculates→Stripe
Draft invoice→Teacher
Approves place→Stripe
Sends + collects

After payment

Verified Stripe webhook updates booking status. Stripe sends receipt and handles reminders.

No place / error?

Hold or reject; do not send invoice. Draft ≠ reservation. Define confirmation and capacity rules with owner.

INVESTIGATE / QK LESSONS × BUILD11

The missing bits.

A real booking has constraints a design preview doesn’t.

Returning families

Billing email is hidden. A name or phone is not proof of identity. Ask owner whether to always collect billing email or verify an existing customer match. Approve discount eligibility.

Multiple children

Up to three children; days and extended hours are shared. Ask whether dates can differ and how extras are charged per child/day. Don’t guess.

Private by default

Medical/support notes, DOB and consent stay in restricted QL records. Stripe receives billing contact, invoice lines and an opaque booking reference only.

SECURITY / QK LESSONS × BUILD15

Don’t invite bots to enrol.

Browser validation is not security.

Turnstile

Cloudflare test keys; server calls Siteverify. Reject invalid, expired or replayed tokens.

Honeypot + limits

Hidden bot trap as secondary signal. Rate-limit form submissions and notification emails. No open mail relay.

Validate server-side

Allowlist dates/options, constrain lengths, escape displayed values, parameterise database queries, recalculate price.

Protect records

Credentials outside public root and GitHub. Restricted storage, logs and backups. Adult-only approval with authentication and CSRF protection. Signed webhooks; deduplicate events.

Apply abuse protection to enquiries and interest forms too. Real family data, credentials and production changes remain with the owner.

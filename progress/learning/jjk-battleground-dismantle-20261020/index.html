03
About 15 min · New ModuleScript

A place for ability rules.

Separate the request router from the code that decides whether an ability is allowed. This is how future characters can grow without a giant handler.

Create / keep / change
ServerScriptService → Services → AbilityService
NEW ModuleScript
  1. In Explorer, right-click Services → insert ModuleScript.
  2. Name it exactly AbilityService (capital A, capital S).
  3. Delete its default example contents (typically local module = {} and return module).
  4. Replace the contents with the single snippet here.
  5. Do not move or rename StateService, CombatService or anything else.

Why these checks? The server verifies that the player has combat state, a living character, a root part, and isn't stunned. It never trusts the client's idea of a hit.

New module contents
REPLACE DEFAULT MODULE CONTENTS 
local StateService = require(script.Parent.StateService)

local AbilityService = {}

function AbilityService.Dismantle(player)
    local state = StateService.GetState(player)
    if not state then
        warn("Dismantle denied: no player state")
        return false
    end

    local character = player.Character
    local humanoid = character and character:FindFirstChildOfClass("Humanoid")
    local root = character and character:FindFirstChild("HumanoidRootPart")

    if not humanoid or humanoid.Health <= 0 or not root then
        warn("Dismantle denied: no living character")
        return false
    end

    if state.IsStunned then
        print("Dismantle denied: stunned")
        return false
    end

    print("[Server] Dismantle approved for", player.Name)
    return true
end

return AbilityService

The module isn't connected to the handler yet; that's the very next mission. It has no damage, cooldown or CE spending.

Visible placeholder, server-controlled
PASTE BELOW THE APPROVAL PRINT 
local slash = Instance.new("Part")
slash.Name = "DismantlePreview"
slash.Anchored = true
slash.CanCollide = false
slash.CanTouch = false
slash.CanQuery = false
slash.Material = Enum.Material.Neon
slash.Color = Color3.fromRGB(240, 240, 255)
slash.Transparency = 0.15
slash.Size = Vector3.new(7, 3, 0.18)
slash.CFrame = root.CFrame
    * CFrame.new(0, 1.2, -6)
    * CFrame.Angles(0, 0, math.rad(28))
slash.Parent = workspace:FindFirstChild("FX") or workspace

game:GetService("Debris"):AddItem(slash, 0.35)

Safe: no hitbox, no target, no HP change, no CE change and no real ability cooldown. This is a preview, not the finished attack.

I press 1 and nothing prints

Check that you're in Play mode, click inside the game viewport, and confirm the CombatClient is a LocalScript. Check the gameProcessed guard and that the 1 branch is inside InputBegan but outside F. Look at the client side of Output.

The client prints but the server doesn't

"Expected 'end'" or red syntax error

Check the elseif goes before the main action chain's closing end. Check that a function has an end, and that the full event connection ends with end). Use Undo for the last edit; retry only that snippet.

Confirm the file is a ModuleScript named AbilityService inside ServerScriptService → Services. Verify that the module ends with exactly one return AbilityService and that StateService exists beside it.

02

Give your arena real names.

While comparing your project with the reference version, we noticed four objects all called SpawnLocation, plus other map objects with generic names like Part.

Why it matters: a team can't build or debug a game if everyone has to click through a pile of anonymous objects to find the right wall or spawn. Good names tell the next developer what each thing is and does. They also make your own scripts much easier to work with.

  1. Open Explorer → Workspace. Click each spawn and see where it is in the arena.
  2. Rename the four existing spawns Spawn1, Spawn2, Spawn3, Spawn4 — the convention in the reference project. Pick a consistent order you can explain.
  3. Find the generic arena Parts. Rename each for its actual job and position. For example: Arena_NorthWall, Arena_SouthWall, Arena_EastWall, Arena_WestWall, or Arena_Floor if it's genuinely the floor.
  4. There are five additional map parts in the version we compared. Make sure all five have useful, unique names, not just the walls.

Rename only. Don't delete, move, resize or change the object type. A SpawnLocation stays a SpawnLocation. Don't rename any scripts, RemoteEvents or service folders.

Quick check Look at Workspace in Explorer. Can another developer tell which spawn, wall or floor object they're looking at without clicking around to investigate?

01 · Reproduce

Does Game Over really stop the game?

Find lBozo(), movePlayers() and the interval that runs every 900 ms in your original code.

Predict

After you touch a spike or bullet, does gravity stop? Is the Game Over message added again?

Test

Lose deliberately. Watch for a few seconds. Try playing again without re-running the editor.

MissionFind the smallest condition that prevents a stopped game from moving its player. Make Game Over happen only once.
Success looks likeAfter a loss, the player stays still, the Game Over text remains, and no duplicate ending is created.
Tutor note · Evidence to listen for

gameRunning = false is only a variable until the interval checks it. A repeating timer is still running. Discuss a guard at the top of the gravity callback and a single terminal-state function.

02 · State

When are the locks really on?

Find isOn, setSolids() and setupLevel().

  1. Press S to make locks clear.
  2. Complete a level.
  3. Try the locks in the next level.
  4. Explain whether isOn agrees with the actual solid sprites.
MissionDecide what the initial lock state of each level should be. Update both the state variable and the solid types together whenever a level starts.
Success looks likeEach new level starts with predictable locks; one press of S has exactly one effect.
Tutor note · Stretch

Ask: “What's the difference between drawing a new map and resetting the rules that govern it?” The point is state coherence, not the particular line of code.

03 · Bullet behaviour

How does a bullet remember its direction?

In 20261031.js, the bullet movement code uses sprite.dx. Sprig treats this as a read-only sprite property. Choose your own place to store left-or-right direction instead.

One small option

let bulletDirections = [];
// Each bullet has a matching entry:
//  1 = right, -1 = left

Reset this array when loading the bullet level. Use the bullet's index to look up and change its direction.

MissionMake the bullets travel, reverse at the map edge and reflect from solid blocks. With locks off, they should no longer bounce from those blocks.
Success looks likeA bullet moves consistently, turns at boundaries, and can end the game when it meets the player.
Tutor note · API check

Sprig documents mutable x/y positions and read-only dx/dy. The refactored version uses its own direction array, not undocumented sprite fields. Test in the editor; local simulations cannot prove rendering behaviour.

04 · Restart

J should mean “try again.”

In the original, J only works while gameRunning is true. That's exactly when you don't need to recover from Game Over.

Decide the rules

After a loss, J retries that level. After a win, J returns to level one.

Test the reset

Are the bullets back? Are the locks solid? Is the message gone? Is the game running?

MissionMake your level-reset function restore everything needed for a clean retry.
Success looks likeJ works after Game Over and after either win; repeatedly pressing it does not make the game speed up.
Tutor note · Timers

If intervals are recreated on every retry without cancelling the old ones, the game can accidentally run multiple clocks. Both supplied solutions install two intervals once and keep them idle while the game is stopped.

05 · Endings

Two ways to win. Neither by accident.

The game has ordinary goals and the secret Qwerty ending. Find both checks in afterInput().

Make the question precise

“Does this map actually contain a target, and is the player covering every target?”

const count = tilesWith(qwerty).length;
const covered = tilesWith(qwerty, player).length;
if (count > 0 && covered === count) {
  // Secret ending
}
MissionKeep one check per ending. Give the secret goal priority if it is reached. Stop gameplay immediately after showing either ending.
Success looks likeAll six levels still work; the normal win and Qwerty Winner each appear once; J starts a new game.
Tutor note · Notice text

Sprig provides clearText(). A pending lock-status timeout must not erase an ending that appears later; cancel it when ending or resetting the game.

08 · Choose what comes next

Now make it yours again.

Once the game is stable, choose a feature because it improves the game — not just because it adds more code.

More interesting bullets

Give each bullet a different starting direction or speed.

A clearer retry

Add an on-screen instruction after Game Over: “Press J to retry”.

Better difficulty curve

Play each level. Does the challenge build in the right order?

Better feel

Experiment with gravity timing. What does 700 ms feel like compared with 900 ms?

Project 01 · Mini-game Build next

Whac-a-Block

A 3 × 3 wall of blocks lights up. Hit the glowstone before the board fills; collect points.

Skills: random numbers · block-hit events · loops · scorekeepingScope: One or two lessons

Original tutorial: Open Martin O’Hanlon · Raspberry Pi worksheet ↗

Build it in small wins

  1. Run the starter imports and show a message in Minecraft.
  2. Build the 3 × 3 stone board. Check it appears in the right place.
  3. Make one block light up, then add randomness.
  4. Detect sword hits, turn glowstone back to stone and count points.

Prove it works

The board appears, a hit changes one glowstone block, and the score increases.

Make it yours

Make the blocks light faster as your score grows.

Python 3 / setup check

This worksheet says to open Python 2 IDLE and includes print hitBlock in an example. Use Python 3 / Thonny and print(hitBlock).

Skills: coordinates · distance · random positions · elapsed timeScope: One lesson + remix

Lava Trap

A floor of lava, a disappearing safe spot, and a game that ends when you fall. You have already tried this one and saw Minecraft return Fail messages.

What you can investigate

  1. Run the block-placement steps separately in a spare world.
  2. Print the player’s starting X, Y and Z coordinates.
  3. Check the lava and stone layers are within world height limits.
  4. Only restore the full loop after the layers work.

Success looks like

A safe stone floor, a lava layer, and a single temporary escape tile, all placed predictably.

Before running old code

Python 3 detective kit.

Most projects here were written years ago. Learn from them; don’t assume they’re copy-and-run.

Spot the differences

Older Python 2Python 3
print xprint(x)
raw_input(...)input(...)
xrange(10)range(10)
5 / 2 → 25 / 2 → 2.5; use // for floor division

Keep the working setup

Use the mcpi library and the Python 3 environment already working on your Raspberry Pi. Don’t install Python 2 because a website asks you to.

Protect your worlds

Try explosions, lava and large setBlocks() operations only in a spare world. Old programs may use fixed coordinates or clear huge areas.

A Python 3 syntax fix does not guarantee that an old library import, command or block type will work. Each project still needs a real Pi test.

Your own version

Don’t stop at “it runs”.

When the original version works, change a rule so it becomes your game.

  1. Save a working copy with a useful filename.
  2. Choose one thing to change: timing, difficulty, blocks, controls, size or scoring.
  3. Predict the result. Change the smallest amount of code you can.
  4. Test it. If something breaks, compare against your saved version.
  5. Show another maker what you changed and how you know it works.

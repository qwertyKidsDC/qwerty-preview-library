Qwerty Labs for Teens

From learning projects to having a creative technology practice of your own.

At some point, following another tutorial stops being the interesting part.

You want to build the bigger game. Make your own AI chatbot. Train a small model and find out what it actually learns. Build a website for someone. Design something properly. Wire something up. Take an idea further than the instructions do.

Qwerty Labs is for that point.

It’s a creative technology studio for teenagers who are ready to make more ambitious things, have more say in what they make, and develop projects they genuinely care about.

Some teens have been coming to the lab for years.

Others first walk through the door as teenagers.

There is no required backstory.

You can arrive with experience, an idea, an obsession with one particular thing, or simply the feeling that you’re ready for something more substantial.

More say. Bigger projects.

Teen projects are less about everybody completing the same activity and more about learning how to make good decisions.

What should this actually do?

What needs to work first?

Which idea is worth keeping?

Why does this bit keep breaking?

Have I made this unnecessarily enormous?

What would make it better?

At the lab, teens gradually take more ownership of those decisions.

Someone newer might start with a project brief from the lab and plenty of support.

Someone more experienced might bring in a game they’ve already been developing, a website, a design problem, a physical build or an idea they don’t yet know how to make.

We help make the project manageable, technically sound and worth finishing.

Without taking it over.

What could you make?

Build your own AI

Build a chatbot or AI character. Train a small model. Experiment with image or sound classification, computer vision, or AI inside a game or interactive project.

Build a game

Roblox, Unity, browser games and whatever comes next. A project might begin with one mechanic and end up involving combat systems, multiplayer logic, player states, UI, progression, balancing and a mildly alarming number of bugs. That’s fine. That’s game development.

Build for the web

Create a website, interactive experience, prototype or digital product. Depending on the project, that can lead into design, UX, accessibility, responsive layouts, hosting, domains, databases and the other things that suddenly matter when something has to work for a real person.

Build something physical

Use electronics, sensors, LEDs, microcontrollers and small computers to make interactive objects, gadgets, installations and experiments. Sometimes the best place for code is not on a screen.

Design something

Not every project needs another script. Teen projects can also involve visual identity, interfaces, prototyping, interaction and communication. The hard part might be deciding what something should look like, how it should behave, what to remove, or whether another version is actually making it better.

Make something we haven’t listed

Please do.

Ways to work at the lab

Teen Studio

Teen Studio is the ongoing home for project work.

Different people can be working on completely different things in the same session.

You might begin with a project brief from the lab, adapt one around your own interests, or bring something of your own.

We help with whatever the project needs next: learning a technique, planning a feature, debugging something stubborn, cutting an idea back to a sensible size, or working out where to go next.

The projects change. The basic rhythm doesn’t: plan → build → test → work out what happened → improve it.

Over time, you should need us differently. That’s a good sign.

Studio Builds

Studio Builds are shorter projects built around an idea worth making.

Rather than signing up to “learn a technology”, you sign up to make something with it.

Upcoming builds might include things like:

  • Build Your Own AI Chatbot
  • Train Your Own AI Model
  • Build a Roblox Game
  • Build a Unity Game
  • Create an Interactive Installation
  • Make Something Strange for the Web

Some might run across several weekly sessions. Others may happen as a weekend or school holiday intensive.

We keep them small enough to leave room for experimentation, detours and the occasional better idea.

Mentored Projects

Already working on something bigger?

We keep a small number of places for teenagers developing substantial projects of their own.

That could be a game, a real website, an AI project, a physical build, a design project, an interactive work or something less cooperative with categories.

These projects get more individual attention because they need it.

We can help with project structure, technical direction, research, debugging, design decisions, scope and the moment when one idea has quietly turned into twelve.

You still make the project.

We help you make better decisions about it.

Mentored Project places are limited.

Not for manufactured exclusivity.

Because properly mentoring a substantial project takes proper attention.

You don’t need to know everything first.

There isn’t a conveyor belt of Coding Level 1, Coding Level 2 and Coding Level 3 here.

We look at what you already know, what you’re interested in and what you’re ready to take on next.

Sometimes you need somebody to teach you something directly.

Sometimes you need an example.

Sometimes you need a second pair of eyes on a bug that has been wasting your afternoon.

And sometimes you already know enough technically.

What you need is help thinking through the project.

That shift matters.

The aim isn’t to become independent by never asking for help.

It’s to get better at knowing what to try, what to ask, what to test and what to do next.

It can also be fun.

Teen work can get technically sophisticated here.

The lab still doesn’t need to feel like school, an exam course or junior corporate training.

We’re not trying to turn every teenager into a software engineer.

We don’t organise our work around competitions.

And nobody needs to turn a hobby into a career plan for it to be worth taking seriously.

You are allowed to care deeply about making an excellent Roblox game because you want to make an excellent Roblox game.

Along the way, you may end up learning software architecture, design, research, project planning, accessibility, electronics, AI, debugging or how to explain a complicated idea to somebody else.

That tends to happen when the project is good enough to demand it.

Growing up at the lab

Tiarna started weekly sessions at QwertyKids in 2020 when she was nine. A few years later, she wrote about what coming here felt like from her side of the desk.

She wrote about coding, but also building things, learning new things, interacting with other people and being able to belong even if you’re quiet.

At QwertyKids, you’ll never feel left out even if you’re not one to talk.

She’s now 15, and the work has grown with her.

What this can look like

Henry: Building a game system

Henry first came to the lab as a teenager.

He was already interested in making an ambitious Roblox battleground game, and the project quickly became much more than writing individual scripts.

Combat involves attacks, cooldowns, player states, movement, blocking, health, UI, respawning and multiplayer communication. Each part affects the others.

So the work became about systems.

We’ve worked through those systems piece by piece, including one of the fundamental rules of multiplayer game development:

Client asks. Server decides.

As the project has grown, Henry has taken more responsibility for defining how things should behave before trying to build them.

He isn’t working through a Roblox course.

He is learning how to direct a complicated game project.

Tiarna: Building for a real person

A website becomes much more interesting when somebody is actually going to use it.

Tiarna’s ecommerce project began with HTML and CSS, then widened into the decisions around the code.

Who is the site for?

What do they need?

How should the information be organised?

What happens on a phone?

Is it accessible?

What is the difference between the domain, the hosting and the website itself?

Should this part be built from scratch at all?

The project has involved user needs, requirements, accessibility, infrastructure and platform choices alongside the code.

Because once a project is real, the code is only part of the job.

Chloe: Developing a visual identity

Chloe’s logo design work has been a different kind of technical project.

The tools matter, but the difficult part is judgement.

Trying directions.

Comparing them.

Working out what is distinctive and what is merely decoration.

Keeping the parts that strengthen the idea and removing the ones that don’t.

Seeing whether a design still works when it is smaller, simpler or used somewhere else.

Making another version when another version is useful.

Stopping when it isn’t.

That process belongs at Qwerty Labs just as much as programming does.

Creative technology includes deciding what to make and how it should feel, not only making the machinery underneath it work.

Chloe + Tiarna: Project Code Cloud

Project Code Cloud started with a problem we kept seeing while teaching.

A child writes code on a laptop.

The code moves through an online service and onto another device.

But where did it actually go?

Chloe and Tiarna built a physical model to make that invisible process visible.

The project combined coding, Raspberry Pi, electronics, LEDs, sound, physical construction and explanation in one interactive system.

It grew through testing, rebuilding and repeatedly asking whether another person would understand what they were seeing.

Project Code Cloud later became one of four Hardware projects chosen as a VIP judge favourite in the Raspberry Pi Foundation’s global Coolest Projects showcase, and the only Australian project among that judge’s favourites.

We don’t normally build things for competitions.

They built it because the problem was worth solving.

The recognition came afterwards.

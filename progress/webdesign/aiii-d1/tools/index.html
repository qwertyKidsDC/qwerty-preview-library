HOW WE USE TOOLS

Learn enough to make the next thing possible.

We use coding, electronics, AI, robotics, design tools and whatever else the project asks for. The aim is not to collect software skills for their own sake. It is to have enough command of a tool to make an idea behave in the real world.

Sometimes that means learning a new language. Sometimes it means discovering that cardboard, a sensor and six lines of code solve the problem better than the complicated version.

The project keeps the learning honest: you find out quickly which parts you understand, which parts you have only copied, and what you need to work out next.

CODE

Make the behaviour.

Games, interactions, logic, websites, physical systems and small useful tools.

ELECTRONICS

Give it inputs and outputs.

Lights, buttons, sensors, motors and the useful mess between software and objects.

AI

Use it as material.

Generate, analyse, automate, prototype, question.

THE RULE

The tool earns its place.

If it does not make the thing more interesting, more useful or more possible, we probably do not need it.

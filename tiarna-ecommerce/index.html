SHOP?!

The project changed. That’s normal.

A simple site mainly publishes information. A shop also has to handle products, stock, money, customer data, orders, confirmations, errors and trust.

This is no longer just “make some pages look good”. It is now a tiny software + business system.

Operations

Rule #1: scope changes are information.Don’t panic-code.

Persona → scenario → use case

A persona describes a kind of person. A use case puts that person in motion.

Persona

Who are they? What matters to them?

Scenario

What situation are they in right now?

Use case

What are they trying to accomplish, and what has to happen?

tiny_example.txt

Persona: customer who discovers the brand on Instagram and shops on a phone.

Scenario: they see a product they like while on the bus.

Use case: they need to check the item, choose any options, understand delivery cost, pay, and know the order worked.

Personas stop being posters here.They start making design decisions.

Start with a story. Then make it real.

User story

“As a mobile shopper, I want to know the full cost before paying, so that I can decide confidently.”

Trigger

Buy one product.
Main path
Product → options → cart → delivery → payment → confirmation.
Exceptions

A use case exposes the invisible requirements hiding behind a pretty page.
Use cases are requirements detectors.Very handy beasts.

REAL-WORLD UX DETOUR

A “simple website” can become a $96.5m problem

The Bureau of Meteorology rebuilt its website after years of work and public beta testing. When the new site launched in October 2025, many regular users still struggled with things that had once felt automatic.

The visible bit

ABC reported about $4.1m for the front-end redesign.

The whole iceberg

ABC reported $96.5m overall, including the wider website build, launch and security testing.

The useful question is not “how can a website cost that much?” It is: what else are you really building when people depend on the website?

Side quest · UX
10

“The information is still there” isn’t enough

Regular users had built mental models: they knew where to click, what the radar looked like and which shortcuts got them to the answer fast. Changing those patterns created friction even when the underlying data still existed.

Mental models

People remember how a system behaves, not just its labels.

Defaults

A useful feature can feel “missing” if the new default hides it.

Hierarchy

Important information cannot require archaeological work.

Wayfinding

Familiar landmarks, quick links and clear paths help people stay oriented.

See what BOM changed in September 2026↗ UPDATE
Modernise what needs modernising.Protect what already works.

Now steal the lesson for your friend’s shop

Your shop will also have first-time visitors, repeat visitors, an owner who needs to update it, and people who arrive with different expectations.

Navigation

Can a first-time buyer and a repeat buyer both find what they need?

Defaults

What might be preselected: size, delivery, pickup, quantity? Who could that confuse?

Search + labels

Critical details

What must never be hard to find: price, size, stock, delivery, returns?

A good test is a task, not “do you like it?” Give someone something to accomplish, watch quietly, and notice where they hesitate.

Internet basics
13

What does “register a domain” mean?

You don’t buy a domain forever. You register the right to use it for a period of time through a registrar, then keep renewing it.

Registrar

The company that handles the domain registration.

Registrant

The person or organisation recorded as the holder of the domain.

Renewal

Registration expires if it is not renewed. Ownership/admin details matter.

DNS settings

These tell the domain which services should answer for the website, email and more.

For a real client/friend project: work out whose name/account should own the domain before clicking “Buy”.
Domain registration is an ongoing responsibility.Not a file download.
Internet basics
14

So what is hosting?

A website needs computers connected to the internet to serve its pages, code, images and data when someone visits. Hosting is the service that provides that environment.

request → response

Your browser: “Hello. Can I have the product page?”

Server: “Yep. Here’s the HTML, CSS, JavaScript, images and whatever data the page needs.”

Self-hosted WordPress

You arrange a host, then install/run WordPress there.

Shopify

Hosting is part of the hosted commerce platform, so you don’t separately manage the web server.

Domain and hosting can be bought from different companies.They meet through DNS.
Systems
15

CMS = Content Management System

A CMS gives people a way to create and manage website content without opening the source files every time.

Without a CMS

Edit HTML/CSS files → upload/deploy → repeat.

With a CMS

Log in → edit pages/products/media in an admin interface → publish.

WordPress is an open-source publishing platform/CMS. Its plugin system lets you add functionality without rebuilding the core software.

Open: WordPress.org↗ CMS Open: WordPress — Introduction to Plugins↗ PLUGINS
The owner should not need you to change a price.That’s a clue.
Systems
16

Core + extensions

Modern platforms are often built as a useful core that can be extended with plugins, apps or integrations.

Core

The platform’s built-in features.

Plugin / app

Adds a capability: forms, bookings, reviews, shipping, analytics…

Integration

Connects the site to another service.

Plugins are powerful, but every extra moving part can bring cost, maintenance, compatibility, privacy and accessibility questions.

Translation: “There’s an app for that” is the beginning of a decision, not the end of one.

Extend deliberately.Avoid plugin confetti.

Accessibility
19

Accessibility is part of the design

Not a “fix it at the end” checkbox. People need to be able to perceive, understand and operate the site in different ways.

In Australia, the Australian Human Rights Commission points digital product teams to technical standards and guidance that support equal access for people with disability. WCAG is the main international web-content standard.

Open: Australian Human Rights Commission — digital accessibility standards + guidelines↗ AU Open: W3C — WCAG overview↗ W3C
For this project: accessibility changes our colours, structure, controls, text, forms, images and testing.
Good UX includes more people.That’s the job.
Accessibility
20

WCAG’s four big ideas: POUR

PPerceivable

Can people get the information?

OOperable

Can they use the controls and navigation?

UUnderstandable

Does the interface and language make sense?

RRobust

Can different browsers and assistive technologies interpret it?

WCAG 2.2 has testable success criteria at three conformance levels: A, AA and AAA.

POUR = a thinking tool.Not just an acronym to memorise.
Accessibility
21

What does this change in the actual build?

Structure

Logical headings, landmarks, labels, real buttons and links.

Keyboard

Can someone reach and use everything without a mouse?

Images

Useful alt text when the image carries meaning.

Forms

Clear labels, instructions and errors that don’t rely on colour alone.

Zoom + layout

Does the site still work when text gets larger or the viewport gets narrow?

Colour + focus

Sufficient contrast and visible keyboard focus.

Accessibility is not “make it dull”. It is “make the design survive more real-world conditions”.
Design for variation.Not for one perfect user.
Accessibility · Colour
22

Chloe already caught this

The Qwerty Labs palette exploration already includes a Colour contrast adjustment from the earlier “Colder” variation. That is design-system thinking: don’t just choose colours — decide how they are allowed to work together.

For normal text, WCAG AA requires at least 4.5:1 contrast. Large text can use 3:1. Here is what the current palette does when we measure some useful pairings:

#020020 on #F1F8F819.08:1 · AAA
#020020 on #F66DC17.70:1 · AAA
#020020 on #92D64411.65:1 · AAA
#020020 on #FF90299.06:1 · AAA
#020020 on #4C69E34.34:1 · not AA for normal text
#F1F8F8 on #4C69E34.40:1 · not AA for normal text
The useful lesson is not “fix the blue”. It is “give every colour a job”. Blue can stay a strong accent/display colour while the accessible pairings do the reading work.
Real Qwerty example: Chloe’s contrast adjustment.Palette ≠ permission to use every pairing.

Accessibility testing is a toolkit

W3C maintains a filterable list of evaluation tools for websites, mobile apps, documents and source code. Automated checks are useful, but they’re one part of evaluation.

W3C — Web Accessibility Evaluation Tools List↗ TOOLBOX

Automated

Fast at finding some detectable failures.

Manual

Keyboard testing, zoom, reading order, labels, meaning and task completion.

A green automated score ≠ “accessible”.Humans still required.
